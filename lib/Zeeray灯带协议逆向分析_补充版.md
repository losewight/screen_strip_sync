# Zeeray 氛围灯带 PC 串口通信协议逆向工程技术文档

> **文档版本**：v2.0（补充版）
> **逆向方法**：USB 串口全量抓包（Free Serial Port Monitor）+ 黑盒压力测试
> **抓包固件**：`2.1.8_0039`
> **设备型号**：`philips.light.strip3`（飞利浦智睿灯带三代，ESP32 + CH340）
> **适用场景**：C++ 后端引擎 + Dart/Flutter Desktop 前端的 PC 屏幕同步氛围光驱动开发

## 一、硬件与物理层基础配置

### 1.1 硬件拓扑

| 项目 | 规格 |
|------|------|
| 灯珠数量 | **20 颗**物理 RGB 灯珠（驱动 IC） |
| 灯带长度 | 2 米（`get_length` 返回 `2`） |
| 主控芯片 | ESP32 |
| USB 转串口 | CH340（USB 转 TTL） |
| 设备标识 | 米家模型 `philips.light.strip3` |

### 1.2 串口参数

| 参数 | 值 |
|------|-----|
| 波特率 (Baud Rate) | `230400` |
| 数据位 (Data Bits) | `8` |
| 停止位 (Stop Bits) | `1` |
| 校验位 (Parity) | `None` |
| 硬件流控 (Flow Control) | `None`（FlowReplace = `0x0`） |
| DTR 控制 | `SERIAL_DTR_CONTROL`（置位） |
| RTS 控制 | 清除（CLR_RTS） |

### 1.3 通信模式

* 纯 **ASCII 文本协议**。
* **所有**下发指令必须以回车换行符 `\r\n`（CRLF, `0x0D 0x0A`）作为终止符。
* 设备响应同样以 `\r\n` 结尾。

### 1.4 串口底层初始化时序（Windows Serial API 抓包佐证）

官方 PC 软件在打开串口后，底层执行了以下 Windows 串口 API 调用序列，C++ 端应严格复现：

```
1. IOCTL_SERIAL_SET_BAUD_RATE      → 230400
2. IOCTL_SERIAL_CLR_RTS            → 清除 RTS
3. IOCTL_SERIAL_SET_DTR            → 置位 DTR
4. IOCTL_SERIAL_SET_LINE_CONTROL   → Stop=1, Parity=No, Data=8
5. IOCTL_SERIAL_SET_CHARS          → XON=0x11, XOFF=0x13, 其余=0x00
6. IOCTL_SERIAL_SET_HANDFLOW       → ControlLines=DTR_CONTROL, FlowControl=0x0(无流控)
7. IOCTL_SERIAL_PURGE              → TXABORT|RXABORT|TXCLEAR|RXCLEAR (0xF) 清空缓冲
8. IOCTL_SERIAL_SET_TIMEOUTS       → ReadInterval=MAX_UINT, 其余=0（非阻塞读）
9. IOCTL_SERIAL_SET_WAIT_MASK      → RXCHAR|TXEMPTY|DSR (0x15) 事件掩码
```

> **C++ 实现要点**：使用 `CreateFile` + `SetCommState` / `SetCommTimeouts` / `PurgeComm` / `SetCommMask` 等 Win32 API 复现此序列。ReadIntervalTimeout 设为 `MAXDWORD` 表示无数据时立即返回，避免读取线程阻塞。

## 二、工业级标准握手序列 (Handshake)

### 2.1 核心握手三步曲

为了从设备内置的 Wi-Fi（米家 App）抢占控制权，PC 端在建立串口连接后，必须严格按顺序发送以下初始化指令：

#### 步骤 1：声明 PC 就绪

```
TX: set_pc_available 1\r\n
RX: ok\r\n
```

#### 步骤 2：设置底层平滑过渡延迟

```
TX: set_usb_dim_time 20\r\n
RX: ok\r\n
```

* `20` 为十进制毫秒级延迟值，确保 60FPS 下的画面平滑度。
* 此值控制固件内部帧间渐变插值步长，值越大过渡越柔和但延迟越高。

#### 步骤 3：正式抢占接管权

```
TX: set_pc_linkage 1\r\n
RX: ok\r\nrep_power 1\r\nrep_pc_linkage 1\r\n
```

* 收到 `rep_power 1` 和 `rep_pc_linkage 1` 代表 C++ 引擎已完全接管灯带，可开始下发高频渲染帧。
* **抓包实测响应为单次读取 35 字节**：`ok\r\nrep_power 1\r\nrep_pc_linkage 1\r\n`（设备将多条响应合并为一次发送）。

### 2.2 完整握手时序图

```
PC                                          ESP32
 │                                            │
 │  set_pc_available 1\r\n                    │
 │──────────────────────────────────────────→ │
 │                                  ok\r\n    │
 │ ←─────────────────────────────────────────│
 │                                            │
 │  set_usb_dim_time 20\r\n                   │
 │──────────────────────────────────────────→ │
 │                                  ok\r\n    │
 │ ←─────────────────────────────────────────│
 │                                            │
 │  set_pc_linkage 1\r\n                      │
 │──────────────────────────────────────────→ │
 │     ok\r\nrep_power 1\r\nrep_pc_linkage 1\r\n
 │ ←─────────────────────────────────────────│
 │                                            │
 │  === 接管成功，开始下发渲染帧 ===          │
```

## 四、设备状态报告机制（抓包新发现）

### 4.1 全量状态报告

当执行 `set_power 1`（开机）时，设备除了返回 `ok\r\n` 外，还会**主动推送一包完整的设备状态报告**（抓包实测 148 字节）：

```
rep_length 2\r\n
rep_available 0\r\n
rep_tv_power 0\r\n
rep_linkage 0\r\n
rep_power 0\r\n
rep_bright 100\r\n
rep_pc_available 1\r\n
rep_pc_linkage 0\r\n
rep_master_type 0\r\n
```

### 4.2 状态字段释义

| 字段 | 示例值 | 类型 | 说明 |
|------|--------|------|------|
| `rep_length` | `2` | 十进制 | 灯带物理长度（米） |
| `rep_available` | `0` | 0/1 | 设备可用性（米家云端在线状态） |
| `rep_tv_power` | `0` | 0/1 | TV 同步电源状态 |
| `rep_linkage` | `0` | 0/1 | 米家 App 联动状态 |
| `rep_power` | `0` | 0/1 | 当前电源开关状态 |
| `rep_bright` | `100` | 十进制 | 设备级全局亮度（0-100%，**十进制**） |
| `rep_pc_available` | `1` | 0/1 | PC 可用状态（是否已声明 `set_pc_available`） |
| `rep_pc_linkage` | `0` | 0/1 | PC 联动接管状态 |
| `rep_master_type` | `0` | 0/1 | 主控类型（0=米家，1=PC） |

> **重要区分**：`rep_bright` 报告的亮度为**十进制**（如 `100` = 100%），而 `set_rgb_pc` 帧指令中的 `{Brightness}` 参数为**十六进制**（如 `64` = 100%）。C++ 端在解析状态报告与封装帧指令时需注意进制差异。

## 五、核心流光溢彩渲染帧协议 (Render Frame)

### 5.1 指令基本结构

固件完全不支持局部增量更新，每一帧必须下发整条灯带的全量状态。

```
set_rgb_pc {FrameID} 00 {Brightness} {HEX1} {Step1} {HEX2} {Step2} ... \r\n
```

### 5.2 参数详解

| 参数 | 格式 | 说明 |
|------|------|------|
| `{FrameID}` | 4 位十六进制 | 自增序列号，用于单片机防抖与防丢包。每发一帧递增 1（`0001` → `0002` → ... → `0009` → `000a` → `000b` → ... → `ffff` → 回绕 `0000`） |
| `00` | 固定占位符 | 抓包确认始终为 `00`，推测为保留字段或模式标记 |
| `{Brightness}` | 2 位十六进制 | 全局亮度。**十六进制值 = 十进制百分比**：`64` = 100%，`63` = 99%，`32` = 50%，`19` = 25%，`01` = 1% |
| `{HEXn}` | 6 位小写十六进制 | RGB 颜色值（如纯红 `ff0000`，浅蓝 `00a3fe`） |
| `{Stepn}` | 十进制整数 | 步长：当前颜色占据几颗物理灯珠 |

### 5.3 黄金强制规则

> **一条完整指令内，所有 Step 数值累加总和，必须严格等于十进制 20（即物理灯珠总数）。**

### 5.4 亮度值参考表（抓包实测）

| 十六进制 | 十进制 | 百分比 | 抓包出现场景 |
|----------|--------|--------|-------------|
| `64` | 100 | 100% | 满亮度（文档约定） |
| `63` | 99 | 99% | 官方软件默认工作亮度 |
| `61` | 97 | 97% | 高频渲染帧实测 |
| `20` | 32 | 32% | 渐变过渡帧 |
| `1f` | 31 | 31% | 渐变过渡帧 |
| `19` | 25 | 25% | 低亮度场景 |
| `01` | 1 | 1% | 暗场/关灯过渡帧 |

### 5.5 渲染帧无响应机制

> **抓包确认**：`set_rgb_pc` 渲染帧指令**不产生任何设备响应**。设备静默接收并执行，不返回 `ok` 或其他确认。C++ 端不应在发送渲染帧后等待 RX 数据，否则将导致线程阻塞。渲染帧为**纯 fire-and-forget 模式**。

### 5.6 抓包实测帧时序分析

从抓包时间戳提取的高频渲染帧间隔：

| 阶段 | 帧间隔 | 等效 FPS | 说明 |
|------|--------|----------|------|
| 初始测试帧 (0001-0004) | ~5000ms | 0.2 FPS | 手动/低频测试 |
| 高频渲染帧 (0005+) | ~30-35ms | **~28-33 FPS** | 正常屏幕同步模式 |
| 模式切换帧 | ~130ms | ~7 FPS | 亮度/场景突变过渡 |
| 末尾稳态帧 | ~30-35ms | ~28-33 FPS | 持续渲染 |

> **C++ 时序建议**：渲染循环目标定在 30ms/帧（≈33FPS），在保证视觉流畅的同时留出串口发送的余量。230400 波特率下，110 字节指令的发送时间约 4.8ms，完全满足 33FPS 需求。

## 六、致命内存溢出 Bug 与 10 段终极渲染方案

### 6.1 官方固件的"128 字节死亡红线"

* **黑盒测试结果**：ESP32 固件内部的串口文本解析器存在极其严重的内存溢出 Bug（RX Buffer Limit 约为 128 字节）。
* **现象**：如果在一条指令中实现真正的 20 段独立控制（Step 全部为 1，发送 20 个颜色参数），该字符串长度将突破 180 字节，直接导致单片机内存越界并触发 Hard Fault 彻底死机。
* **官方软件的妥协**：将画面压缩为 5 段控制（Step 写死为 4），严重损失画质。

### 6.2 官方 5 段方案抓包佐证

抓包捕获到的官方软件实际下发帧（5 段 × Step 4 = 20）：

```
set_rgb_pc 0001 00 63 00a3fe 4 00a3fe 4 00a3fe 4 00a3fe 4 00a3fe 4\r\n
```

* 5 个颜色段，每段 Step=4，合计 5×4=20 ✓
* 字符串总长约 70 字节，远低于 128 字节红线
* 亮度 `63`（99%），颜色 `00a3fe`（浅蓝色）

暗场关灯帧示例（亮度 1%，全黑）：

```
set_rgb_pc 0005 00 01 000000 4 000000 4 000000 4 000000 4 000000 4\r\n
```

渐变唤醒帧序列示例（亮度从 25% 渐升至 32%）：

```
set_rgb_pc 0008 00 19 00080d 4 00080d 4 00080d 4 00080d 4 00080d 4\r\n
set_rgb_pc 0009 00 19 000a10 4 000a10 4 000a10 4 000a10 4 000a10 4\r\n
set_rgb_pc 000a 00 19 000d14 4 000d14 4 000d14 4 000d14 4 000d14 4\r\n
...
set_rgb_pc 001d 00 20 003654 4 003654 4 003654 4 003654 4 003654 4\r\n
```

### 6.3 C++ 极限榨干性能方案：对称的 10 段渲染架构

为了在绝对安全的内存范围内实现最高分辨率，C++ 后端抓屏与封装算法必须写死为 **10 段控制方案**：

| 项目 | 官方方案 | 我们的 10 段方案 |
|------|---------|-----------------|
| 段数 | 5 段 | **10 段** |
| 每段 Step | 4 | **2** |
| 总灯珠覆盖 | 5×4=20 ✓ | 10×2=20 ✓ |
| 指令字符串长度 | ~70 字节 | **~110 字节** |
| 安全裕度 | 58 字节 | 18 字节（仍 < 128 红线） |
| 空间分辨率 | 20% | **10%**（翻倍） |

* **逻辑切片**：将屏幕边缘划分为 10 个抓取区域。
* **步长锁定**：每个颜色对应 2 颗物理灯珠，即 `Step` 永远锁定为 `2`。（10 × 2 = 20）
* **安全载荷**：10 段颜色的整条指令字符串长度固定在 **110 字节左右**，完美避开 128 字节崩溃红线。

### 6.4 终极 10 段安全封包示例

```
set_rgb_pc 010a 00 64 ff0000 2 00ff00 2 0000ff 2 ffff00 2 00ffff 2 ff00ff 2 ffffff 2 ff8800 2 8800ff 2 ff0088 2\r\n
```

**C++ snprintf 模板**（严格对照）：

```c
// buf 大小至少 128 字节
snprintf(buf, 128,
    "set_rgb_pc %04x 00 %02x %06x 2 %06x 2 %06x 2 %06x 2 %06x 2 %06x 2 %06x 2 %06x 2 %06x 2 %06x 2\r\n",
    frame_id,     // 4 位 hex 自增
    brightness,   // 2 位 hex 亮度
    rgb[0], rgb[1], rgb[2], rgb[3], rgb[4], rgb[5],
    rgb[6], rgb[7], rgb[8], rgb[9]  // 10 段颜色，每段 6 位 hex
);
```

## 七、电源控制指令（抓包新发现）

除 PC 联动控制外，固件还支持独立的电源开关指令：

### 7.1 关闭电源

```
TX: set_power 0\r\n
RX: ok\r\n
    rep_power 0\r\n
    rep_pc_linkage 0\r\n
```

* 关闭电源时，设备会自动断开 PC 联动（`rep_pc_linkage 0`）。

### 7.2 开启电源

```
TX: set_power 1\r\n
RX: ok\r\n
    [全量状态报告，详见第四章]
    rep_power 1\r\n
```

* 开启电源时，设备会推送完整的设备状态报告（`rep_length`、`rep_bright` 等 9 个字段），最后以 `rep_power 1` 确认。

### 7.3 电源与联动的关系

```
                    set_pc_linkage 1
  米家控制 ─────────────────────────────→ PC 接管
     ↑                                      │
     │   set_pc_linkage 0                   │
     │←─────────────────────────────────────│
     │                                      │
     │   set_power 0 (关灯+释放联动)        │
     │←─────────────────────────────────────│
     │                                      │
     │   set_power 1 (开灯, 需重新联动)     │
     │←─────────────────────────────────────│
```

> **C++ 生命周期建议**：软件退出时先发 `set_pc_linkage 0` 释放联动，再发 `set_power 0` 关灯。重新连接时先发 `set_power 1` 开灯，再走握手三步曲重新接管。

## 八、控制权释放与生命周期退出

当 Dart 前端用户点击"断开"或关闭软件时，C++ 核心必须下发释放指令，将控制权交还给单片机（以便米家 App 重新接管）：

### 8.1 标准退出序列

```
步骤 1：释放 PC 联动
TX: set_pc_linkage 0\r\n
RX: ok\r\nrep_pc_linkage 0\r\n

步骤 2（可选）：关闭电源（物理关灯）
TX: set_power 0\r\n
RX: ok\r\n
    rep_power 0\r\n
    rep_pc_linkage 0\r\n
```

### 8.2 抓包佐证：完整会话退出流程

抓包末尾捕获到的实际退出序列（11:38:50 - 11:38:52）：

```
[11:38:50.630] TX: set_pc_linkage 0\r\n       ← 释放联动
[11:38:50.680] RX: ok\r\nrep_pc_linkage 0\r\n  ← 确认释放

[11:38:52.295] TX: set_power 0\r\n             ← 关灯
[11:38:52.354] RX: ok\r\n                      ← 确认关灯
[11:38:52.385] RX: rep_power 0\r\n             ← 状态推送：已关灯
```

## 九、完整协议指令速查表

## 十、C++ / Dart 架构开发约束（补充）

### 10.1 架构分工

| 层 | 语言 | 职责 |
|----|------|------|
| **核心引擎 (.dll)** | C++ | DXGI 高性能屏幕显存抓取、Stride 内存对齐、10 段边缘色彩降维与跳跃采样、帧指令 `snprintf` 封装、串口 `WriteFile` 发送 |
| **UI 与异步控制** | Dart/Flutter | 现代跨平台 UI、状态管理、`dart:ffi` 零拷贝读取 C++ 计算结果、单线程 Event Loop 处理高频串口通信与 EMA 阻尼算法 |

### 10.2 C++ 端关键工程约束

1. **显存对齐 (Stride)**：Windows 截屏画面的显存存在 Stride（内存对齐填充字节）。必须使用 `BitmapData.LockBits` 或 DXGI 级别的指针锁，严格计算 `Stride` 和 `RowOffset` 进行纯指针遍历，否则会将填充字节当作颜色值读取，导致亮度极值飙升与"画面亮闪"。

2. **线程安全**：任何向串口写入指令的操作（特别是生命周期结束时的关灯指令）都必须在互斥锁（`std::mutex` / `lock`）保护下执行。UI 调参线程与渲染线程不得竞争串口写入。

3. **硬件降噪（blurStep）**：不使用图形滤镜算法降噪，而是在显存遍历中引入 `blurStep`（采样步长）。数值越大跳过的像素越多，实现物理级硬件降噪的同时大幅降低 CPU 占用。

4. **帧间微延时**：每次 `WriteFile` 后需辅以微小延时（`Sleep(1)` ~ `Sleep(2)`），防止连续高频写入冲死控制器缓存。抓包实测官方软件帧间隔最小约 30ms。

5. **开机自启容错**：电脑开机或从睡眠唤醒瞬间，主板 USB 供电和 CH340 驱动尚未加载完毕。程序不能"秒启"光效，必须引入**容错延时自启机制**：延迟 2-3 秒后尝试连接，若失败则每隔 2 秒重试（最高 5 次）。

### 10.3 Dart 端关键工程约束

1. **EMA 时间阻尼**：引入指数移动平均算法消除画面剧烈变化时的灯光闪烁：`output = alpha * input + (1 - alpha) * prev_output`，`alpha` 由用户可调。

2. **暗场断电**：自定义暗黑阈值，当画面极暗（均值低于阈值）时切断亮度至 `01`（1%），防止灯带发出灰白底噪光。

3. **纯色模式直通**：纯色模式绕过所有平滑和暗场算法，将原生 RGB 绝对精准地发送至硬件。

4. **配置持久化**：用户所有操作（端口、滑块数值、颜色选择）实时写入本地 JSON 文件，实现断电记忆。

5. **系统生命周期拦截**：拦截 Windows 关机/注销/休眠广播（`SystemEvents.SessionEnding` / `PowerModeChanged`），实现精准的"休眠断电关灯"与"唤醒重连亮灯"。
